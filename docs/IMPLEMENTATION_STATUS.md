## 本次重点调整

### 手机号与学号

- 不提供自助注册，账号由学校统一开通并保存在数据库中，没有账号数据无法登录。
- 首次登录后如资料不完整，进入资料完善页；学号、昵称为必填/可编辑项。
- 手机号、邮箱首次补录可直接生效，已有值再修改会生成待审核申请，管理员通过后才写入账号。
- 学号、昵称仍可直接修改；手机号、学号保持数据库唯一约束。

### 登录优先与本地业务数据

- 移动端根网址固定跳转登录页，登录后若资料不完整则先进入资料完善页，再进入 `/app/home`。
- PC 管理端根网址固定跳转 `/login`；业务后端根地址也会重定向到 PC 管理端登录页。
- `campus_card_account` 保存用户校园卡号、余额、状态和最后交易时间。
- 数据库工具支持 `get_card_balance`，可按当前用户、学号或卡号查询。
- 普通用户只能查询本人余额，管理员可以查询已入库学生余额。
- 示例：“查询学号为01的学生的校园卡余额”会由数据库工具返回余额，而不是让文档检索或 Web Search 猜测。

### 游客预览

- 登录页提供“游客预览”入口。
- 预览页只展示静态界面示意，不请求真实分类、文档或问答接口。
- 首页、检索、详情、下载和问答 API 均要求登录，游客不能获取真实文档数据。
- 该策略比概要设计原稿“游客可查看首页缩略信息”更严格，是本次用户要求的覆盖。

### 管理员与反馈

- 管理员只能进入 PC 管理端，不能登录移动端。
- 管理员调用任何移动问答或会话接口都会返回 403。
- 管理员不能通过内部数据库工具查询学生校园卡余额。
- 后端禁止封禁任何 `ADMIN` 角色账号，前端管理员行不显示封禁按钮。
- 普通用户可以封禁和解封。
- 反馈处理写入 `PROCESSED` 或 `IGNORED`，同时记录处理人和处理时间；刷新后从数据库重新加载状态。

### AI 按问题类型选择来源

系统先判断问题需要哪些来源，再调用对应能力：

1. 文档类问题：只检索 Chroma 知识库，例如“怎么补办校园卡”。
2. 数据库类问题：只查询本地白名单工具，例如“我的账号余额是多少”。
3. 混合问题：同时查询知识库和数据库，例如“余额是多少，并告诉我怎样充值”。
4. Web Search：不作为默认来源；只有本地知识库和数据库均无依据，或问题明确要求最新/实时信息时才补充联网结果。

来源类型通过 `chat_citation` 持久化，并在 SSE 的 `citation` 和 `done` 事件中返回。Web 结果卡片可以打开对应网页，工具和知识库结果显示快照。

### 接口文档

- `/docs` 改为使用项目内置 Swagger UI 静态资源，不再依赖 jsDelivr CDN。
- `/openapi.json` 保持标准 OpenAPI 3.1 输出。

## 与概要设计的差异

1. **游客访问**：原设计允许查看首页缩略信息；现按用户要求改为静态预览，API 全部要求登录。
2. **账号注册**：取消自助注册，改为使用数据库中已存在的账号登录；手机号、邮箱修改需管理员审核。
3. **登录方式**：在用户名、手机号、邮箱基础上增加学号。
4. **接口文档**：使用本地 Swagger 资源，解决国内网络无法加载 CDN 的问题。
5. **Web Search**：保留 Tavily 方式，并新增无需密钥的国内搜索回退，保证演示环境可用。
6. **FAQ**：按概要设计最终版本，常见问题作为普通知识文档维护，不建立独立 FAQ 表。
7. **外部大模型**：支持 OpenAI 兼容接口；未配置密钥时使用抽取式回答，业务功能不中断。

## 业务逻辑优化记录

本轮针对“配置不生效、权限只挡一半、流程可留脏数据”等问题做了一轮收敛：

- 配置项真正生效：下载地址有效期、首页每类文档数、Web Search 开关均读取后台配置；后台修改配置时按业务范围校验（如 `rag.top_k` 1-20、相似度 0-1、下载有效期 30-3600 秒）。
- 文档可见性统一：公开检索、详情、下载令牌、内部 `find_documents` 工具共用同一套“分类启用 + 已发布 + 未删除 + 在有效期内”规则，分类停用后旧下载链接立即失效。
- 文档流程校验：生效日期不得晚于失效日期，过期文档不能发布或直接以 PUBLISHED 新建；日期校验前不落盘，避免上传目录产生孤儿文件；替换 PDF/DOCX 时清空旧解析正文。
- 减少无意义索引：只有标题、分类或原始文件变化才触发重新索引，修改摘要、排序、下载开关不再制造新版本。
- 索引清理：同一版本重试/重排时整版替换切片，避免文档变短后仍召回旧片段。
- 问答链路：会话摘要按系统上下文传给模型，不再被误当成用户发言；大模型流式中断后不再追加整段抽取式兜底；工具查无记录时展示友好提示而非原始 JSON；无依据的本地兜底检索增加召回门槛，并截取命中片段而不是永远返回开头。
- 安全与数据生命周期：敏感词配置命中“索取意图”时追加安全提醒；已删除会话按保留天数物理清理。
- 登录标识：用户名、手机号、邮箱、学号跨字段保持全局唯一，避免同一字符串对应多个账号导致登录歧义。

## 本轮体验与数据优化

在“业务逻辑已收敛”的基础上，本轮继续补齐普通用户能直接感知的部分：

- 登录界面：移动端增加用户名/手机号/学号切换、密码显示切换、记住账号、登录帮助弹窗和内联错误提示；管理端增加记住账号与错误样式；两个端都把网络错误、超时和 5xx 映射成中文提示，后端把 Pydantic 英文校验信息统一转换成“手机号不能少于…个字符”这类中文句子。
- 问答文案：未配置大模型或大模型不可用时，抽取式回答不再拼接 `{"found": true, ...}` 这类原始参数；余额类结果转成“你当前的校园卡余额为 128.50 元，卡号 CARD****0001，账户状态正常”，文档类结果转成「标题：要点」的短列表，网页结果只保留标题与一句摘要。
- 推荐问题：按当前话题给出下一轮可问的问题（余额/充值、挂失/补办、消费/流水、优惠、激活/密码各一组），不再固定推同样三条。
- 问答页：错误提示统一为“回答暂时没能生成，请稍后再试，或换个说法提问”，并收紧 Markdown 标题与代码块样式，避免长回答挤压气泡；普通回答不展示参考来源和技术参数，实时网页回答只保留可核验的日期与链接。
- 演示数据：知识库补充到 26 份文档并覆盖全部 5 个板块（新增补助入账说明、办理领取、图书馆与门禁、余额不足与自动充值、补办进度、消费对账、商户终端、优惠资格变更、临时活动、常见报错、余额流水不一致）；同时预置演示问答会话、点赞/点踩反馈，以及待审核、已通过、已驳回三类资料申请，后台各页面开箱即有数据。
- 余额隐私：移动端“我的”只展示本人余额与脱敏卡号；AI 侧越权查询他人余额直接返回隐私提示并终止检索，不会继续联网或检索知识库。

## 对话业务增强

- 读能力：本人余额、消费明细、分类/商户/日期统计、环比、补助入账解释和余额预测；金额、笔数、占比与预测全部由业务后端计算。
- 写能力：挂失、解挂、补办预约和本地模拟充值统一采用 prepare/commit 两阶段确认；确认令牌一次性、5 分钟有效，重复提交按幂等键返回原工单。
- 工单：状态按 created → submitted → processing → completed 流转，异常进入 failed/cancelled；每次变更写入事件记录，支持按单号或最近一笔查询进度。
- 对话编排：支持单句多意图、相对日期、确认/取消词、本人数据隔离；一句话“先挂失，然后预约后天下午补办”可合并为一段回执。
- 实时信息：联网搜索缺失时会记录 provider、检索词、结果数量和 URL；网页结果连同日期进入模型上下文，最终回答固定附带检索日期与来源链接。
- 数据隔离：`DEMO_MODE=false` 时写接口返回未开放，所有演示写入不连接真实支付或校园卡系统。
